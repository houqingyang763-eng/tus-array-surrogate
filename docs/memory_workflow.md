# 科研记忆管理工作流 v3

## 目标

本 repo 的职责不是替用户设置科研 task，而是帮助用户：

1. 跟进长期科研判断；
2. 记录项目路线变化；
3. 保留可追踪依据；
4. 汇总当前重要但未查清的问题；
5. 方便用户自己决定下一步任务。

---

## 当前长期记忆文件

### `docs/memory.md`

主入口。

写入：

1. 当前状态摘要；
2. 完整时间线；
3. 近期 3-5 个关注方向；
4. 已舍弃 / 已降级路线；
5. 重要判断为什么发生变化。

禁止：

1. 写成聊天流水账；
2. 写成细粒度 todo list；
3. 替用户安排“做 PPT / 汇报 / 完成标准”等任务。

### `docs/ideas.md`

记录未验证但可能有价值的想法。

写入：

1. 从论文获得的启发；
2. 可能有价值但未验证的模型结构、输入输出、loss 或实验设想；
3. 尚不能写入 decisions 的路线苗头。

### `docs/questions.md`

记录真正开放的问题。

写入：

1. 需要问师兄的问题；
2. 需要查论文的问题；
3. 需要实验验证的问题；
4. 当前定义不清、证据不足、风险未明的问题。

已舍弃路线不再作为活跃问题保留，应记录到 `docs/memory.md` 的“已舍弃 / 已降级路线”。

### `docs/decisions.md`

只记录稳定共识。

写入条件：

1. 用户明确确认；
2. 组内反馈已经明确要求；
3. 论文或实验已经提供足够证据；
4. 某条 idea / question 已经被用户确认升级为共识。

### `docs/research_tasks.md`

历史保留文件。

不再主动维护，不再作为日常科研记忆入口。Codex 不应主动新增细粒度 task。

如果用户明确要求整理任务，可以在当前对话中临时总结；只有用户明确要求写入任务文件时，才修改该文件。

## 基础流程

```text
用户自然语言输入 / 论文阅读 / Zotero 内容
-> Codex 先判断：这是时间线记忆、想法、问题，还是稳定结论
-> 优先更新或建议更新 memory.md
-> 必要时再精炼到 ideas.md / questions.md / decisions.md
-> 用户确认后写入
-> Codex 汇报修改摘要和需要人工确认的风险
```

---

## 主动整理流程

当用户表达“总结上文 / 写入 repo 记忆 / 整理项目记忆 / 更新 memory”时：

```text
1. 读取 memory.md、project_concept_v*.md、decisions.md、questions.md、ideas.md
2. 对比当前对话和已有记忆
3. 提出新增 / 修改 / 标记过时建议
4. 用户确认后写入
5. 汇报写入结果和风险点
```

主动整理时，优先使用 `research-memory-curator` skill。

## 近期关注的写法

`memory.md` 中的“近期关注”只保留 3-5 个方向。

每个方向只回答：

1. 关注什么；
2. 为什么重要；
3. 它和当前主线的关系。

不写：

1. 产出物；
2. 完成标准；
3. `todo / doing / done` 状态；
4. “做 PPT / 汇报”这类细任务。

---

## 依据规则

写入长期记忆的内容必须可追踪，不要只写结论。

可接受的依据类型：

```markdown
依据：
- 用户确认：用户明确说了什么。
- 项目文档：来自哪个文件，例如 `docs/project_concept_v3.md`。
- 论文/网页：标题或作者，URL，支持了什么判断。
- GitHub/代码：仓库 URL 或本地文件路径，支持了什么数据结构或实现事实。
- 计算推导：基于哪些数字、公式和结果。
```

---

## 旧内容处理

默认不直接删除历史。

如果旧内容被新判断替代：

1. 对活跃文件，移除或改写已经不再成立的活跃问题；
2. 在 `docs/memory.md` 的“已舍弃 / 已降级路线”记录替代原因；
3. 不覆盖旧版 `project_concept_v*.md`，而是新建版本文件。

---

## 写入前确认

用户输入科研笔记后，先输出归档提案，不直接写文件，除非用户已经明确要求执行某个已确认计划。

建议格式：

```markdown
我建议这样更新项目记忆：

1. memory.md
   - ...

2. ideas.md
   - ...

3. questions.md
   - ...

4. decisions.md
   - ...

5. 暂不写入
   - ...

需要你确认：
- 哪些可以写入？
- 哪些只是临时讨论？
- 哪些需要升级为 decision？
```

---

## 写入后汇报

每次写入后必须汇报：

```markdown
已写入：
- docs/memory.md：新增 / 修改 ...
- docs/ideas.md：新增 / 修改 ...
- docs/questions.md：新增 / 修改 ...
- docs/decisions.md：新增 / 修改 ...

未写入：
- ...

需要人工确认的风险：
- ...
```

如果没有写入某类文件，也要说明原因。

## Zotero 使用边界

Codex 的 Zotero 工具访问的是本机 Zotero Desktop 本地库，不是直接登录云端 Zotero 网页账号。

默认规则：

1. 只有用户明确要求时，才读取 Zotero 条目、附件或全文。
2. 读取 Zotero 默认为只读。
3. 导入、修改、整理 Zotero 条目必须再次确认。
4. 如果本地 API 不可用，先报告状态，不擅自扩大操作范围。
