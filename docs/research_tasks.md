## R001：三篇论文多 Agent 阅读与初版 research taste 校准

状态：`approved / waiting_sources`

### 研究问题

能否通过三篇代表性论文的独立阅读、相互质疑和用户详细批注，形成一套初版的用户科研判断规则，并用第四篇未参与校准的论文做盲测？

### 论文选择要求

三篇论文应覆盖：

1. 用户认为非常重要的主线论文；
2. 有局部方法价值、但不能直接照搬的论文；
3. 表面相关、实际应当降级或放弃的论文。

第四篇作为盲测，不参与 taste 规则形成。

### Agent 分工

主 Agent：

- 控制任务范围；
- 汇总冲突；
- 生成用户批注模板；
- 提炼 taste 候选规则；
- 不直接把候选规则升级为稳定项目结论。

子 Agent A（论文取证）：

- 提取任务、输入输出、网络、数据、实验和原文页码；
- 区分作者声明与实际证据。

子 Agent B（项目迁移）：

- 判断能偷什么、不能偷什么；
- 对照 3D、大区域绝对 pmax、阵元位置 / 法向和单阵元复场路线。

子 Agent C（怀疑者）：

- 尝试推翻迁移判断；
- 检查相位、线性声学、label 成本、几何泛化和证据越界。

### 允许范围

- 读取用户指定的论文、附件、公开代码和项目文档；
- 进行只读网页 / GitHub / Zotero 检索；
- 在 `docs/agent_runs/R001/` 写报告和证据草稿；
- 使用多 Agent 并行处理相互独立的取证任务。

### 禁止事项

- 不修改 `project_concept_v4.md`、`decisions.md`、`memory.md`；
- 不把 Agent 推测写成论文事实；
- 不安装大型依赖；
- 不运行长时间 GPU 任务；
- 不把第四篇盲测论文用于 taste 校准。

### 证据标准

每个关键结论必须标记为以下之一：

```text
论文原文
代码 / 数据实证
实验结果
计算推导
Agent 推测
用户判断
```

论文事实尽量给出页码、图表、公式或章节位置。无法获得原文时必须明确降级置信度。

### 交付物

每篇论文：

1. 一句话项目判断；
2. 输入输出与变量覆盖表；
3. 能偷 / 不能偷；
4. 三个 Agent 的主要分歧；
5. 需要用户重点批注的判断点；
6. 用户必须学习的概念、图表、公式或代码路径。

三篇完成后：

1. `taste_v0` 候选规则；
2. 规则的证据来源和适用边界；
3. 第四篇盲测协议；
4. 与用户判断差异的评分表。

### 用户批注要求

用户对每篇至少标注：

1. 哪些判断正确，为什么；
2. 哪些判断错误，为什么；
3. Codex 漏掉了什么；
4. 哪些事实虽然正确，但对本项目不重要；
5. 用户依据哪一页、哪张图、哪个实验或物理假设做判断。

### 完成标准

1. 三篇论文均完成独立取证、迁移判断和反方审计；
2. 用户完成详细批注；
3. 形成可追踪的 `taste_v0`；
4. 第四篇盲测不泄漏校准答案；
5. 输出盲测差异，而不是只报告“基本一致”。

### 资源预算与停止条件

- 初次试点最多同时使用 3 个子 Agent；
- 单篇论文无法取得全文时停止深读并报告，不用摘要补造细节；
- 多 Agent 结论明显冲突时由主 Agent 保留分歧，不强行统一；
- 遇到需要安装依赖、长时间计算或修改核心文件时停止并请求用户确认。

### 依据

- 用户 2026-07-15 批准四层工作流和多 Agent 论文试点。
- 用户 2026-07-15 同意先让 Codex 阅读三篇论文，再用详细批注形成初版 taste。
- 项目规则要求论文阅读必须服务于 3D 阵列 surrogate 路线判断，而不是只翻译摘要。
