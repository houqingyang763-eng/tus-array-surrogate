## R001：单篇优先的多 Agent 精读与初版 research taste 校准

状态：`review / paper_1`

### 研究问题

能否让多个 Agent 对同一篇论文逐节、逐公式、逐图表精读，分别取证、推导和质疑，在不牺牲阅读深度的前提下形成用户可批注的研究报告；随后再逐篇积累用户的 research taste？

### 已指定论文与执行顺序

1. `Finite difference-embedded UNet for solving transcranial ultrasound frequency-domain wavefield`
2. `Deep neural Helmholtz operators for 3-D elastic wave propagation and inversion`
3. `Learned frequency-domain scattered wavefield solutions using neural operators`

执行原则：

1. 先只精读第一篇，不并行扫读另外两篇；
2. 第一篇完成多 Agent 综合并由用户详细批注后，才启动第二篇；
3. 第三篇同样等待前一篇验收；
4. 三篇完成后再选择第四篇盲测论文。

### “精读”的操作定义

精读不是输出逐字翻译，而是确保正文每个章节、关键段落、公式、图、表、实验设置、附录和限制都进入证据清单。报告必须能回答：

1. 作者每个核心主张由什么证据支持；
2. 数学和物理方法每一步在算什么；
3. 网络结构、数据生成、训练和评价怎样连成完整链路；
4. 哪些细节最值得继续深入研究；
5. 哪些主张被实验真正验证，哪些只是作者解释或 Agent 推测；
6. 对本项目能迁移什么、不能迁移什么，以及原因。

### Agent 分工

主 Agent：

- 控制任务范围；
- 汇总冲突；
- 生成用户批注模板；
- 提炼 taste 候选规则；
- 不直接把候选规则升级为稳定项目结论。

子 Agent A（逐节证据审计）：

- 从第一页到最后一页建立章节、关键段落、公式、图表和实验的证据索引；
- 提取任务、输入输出、网络、数据、实验和原文页码；
- 区分作者声明、实验结果和没有证据支持的解释。

子 Agent B（数学、物理与网络深挖）：

- 逐式解释 Helmholtz / 有限差分嵌入、复数波场表示、网络结构、loss 和训练链路；
- 复算可复算的维度、离散关系和指标；
- 识别真正的新方法与普通 U-Net 组件的边界。

子 Agent C（项目迁移与反方审计）：

- 判断能偷什么、不能偷什么，并主动尝试推翻正面迁移判断；
- 对照 3D、大区域绝对 pmax、阵元位置 / 法向和单阵元复场路线；
- 检查二维到三维、固定源到可变阵元、频域复场到 pmax、数据成本和几何泛化的证据越界。

### 允许范围

- 读取用户指定的论文、附件、公开代码和项目文档；
- 进行只读网页 / GitHub / Zotero 检索；
- 在 `docs/agent_runs/R001/` 写报告和证据草稿；
- 使用多 Agent 并行处理相互独立的取证任务。

### 禁止事项

- 不修改 `project_concept_v4.md`、`decisions.md`、`memory.md`；
- 不把 Agent 推测写成论文事实；
- 不安装大型依赖；
- 不运行长时间 GPU 任务；
- 不把第四篇盲测论文用于 taste 校准。

### 证据标准

每个关键结论必须标记为以下之一：

```text
论文原文
代码 / 数据实证
实验结果
计算推导
Agent 推测
用户判断
```

论文事实尽量给出页码、图表、公式或章节位置。无法获得原文时必须明确降级置信度。

### 交付物

第一篇精读交付：

1. 一句话项目判断；
2. 按论文顺序的逐节阅读地图和页码证据表；
3. 输入输出、固定变量 / 变化变量与数据流；
4. 关键公式逐符号、逐单位、逐步骤解释；
5. 网络结构、有限差分嵌入位置、loss 和训练过程；
6. 图表与实验逐项解读，区分作者声称和实际证明；
7. 能偷 / 不能偷以及迁移到本项目所需的修改；
8. 三个 Agent 的分歧和主 Agent 裁决；
9. 最值得继续深挖的 1-3 个部分；
10. 用户必须学习的概念、公式、图表和判断题；
11. 用户批注模板。

三篇完成后：

1. `taste_v0` 候选规则；
2. 规则的证据来源和适用边界；
3. 第四篇盲测协议；
4. 与用户判断差异的评分表。

### 用户批注要求

用户对每篇至少标注：

1. 哪些判断正确，为什么；
2. 哪些判断错误，为什么；
3. Codex 漏掉了什么；
4. 哪些事实虽然正确，但对本项目不重要；
5. 用户依据哪一页、哪张图、哪个实验或物理假设做判断。

### 完成标准

1. 第一篇每个章节、关键公式、图表和实验均进入证据清单；
2. 三个 Agent 均阅读全文，但分别从证据、技术和反方角度独立输出；
3. 主 Agent 保留分歧并形成可供用户逐项批注的综合报告；
4. 用户完成第一篇详细批注后，才允许启动第二篇；
5. 三篇完成后形成可追踪的 `taste_v0`，第四篇盲测不泄漏校准答案。

### 资源预算与停止条件

- 初次试点最多同时使用 3 个子 Agent，且三个 Agent 只读同一篇论文；
- 不把“多 Agent”理解成同时分摊多篇论文；
- 单篇论文无法取得全文时停止深读并报告，不用摘要补造细节；
- 多 Agent 结论明显冲突时由主 Agent 保留分歧，不强行统一；
- 遇到需要安装依赖、长时间计算或修改核心文件时停止并请求用户确认。
