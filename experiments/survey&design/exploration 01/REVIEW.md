# 问题、机制与创新审查

适用：[MISSION](MISSION.md)；2026-10-16用户批准标准。

## 1. 三次调用

| 时机 | 必须完成的判断 |
| --- | --- |
| 检索前 | 具体困难、拟寻找机制、原文证据目标；先查题名/标识/方法家族 |
| 读论文后 | 实际问题、输入输出、计算作用、收益及适用条件；可借鉴什么 |
| 形成构想后 | 机制查重、计算闭合、三维成本、最小验证与取舍 |

每个对象每阶段审查一次，出现改变判断的新证据才更新。默认单Agent，不生成重复审计报告。

## 2. 从问题出发

固定逻辑链：**核心问题 → 原因假设 → 针对性计算机制 → 相对最近先例的新增部分 → 可区分的验证。**

区分已观测困难、文献解释和本项目假设。不能为了合理化新模块而假定McMg或经典方法存在未观察到的失败。允许提出新的高价值问题，但应交代它与求解目标的关系。

## 3. 文献事实

记录题名/版本/标识、输入输出、真实A是否运行、学习模块替代哪步、训练与推理差别、维度/规模、源/介质变化、收益及条件。保留负向结果，合并版本和共享实验，不把摘要声明升级为正文实证。

真实残差、独立复场形状误差、pmax/焦点、迭代步数和完整耗时分别解释。二维/异领域可以提供机制先例，不因任务不同忽略其新颖性约束。

## 4. 创新判定

对照最接近的已有方法，而非只对照普通U-Net。依次检查：

1. 已有方法的核心运算及其问题是什么？
2. 我们改动哪一步、使用哪些信息、改变何种表示/作用范围/更新关系？
3. 该计算关系是否已在其他领域提出？若是，应归为迁移基线，或明确还存在何种实质改造。
4. 新增部分与目标困难之间有何依据？
5. 哪项直接迁移/简单替换对照及消融能区分贡献？

原样搬用McMg、标准PINN/FNO等、仅换3D/数据集/物理输入不作为创新候选。只给模块新名字或堆叠常见模块也不通过。经典工具可以保留，创新在于针对问题形成的新增计算机制。完整复现或数据集应用具有基线价值，不因此升级为方法贡献。

## 5. 计算闭合与可行性

给出A、右端项、状态、残差、校正及外层更新；标清哪些是物理算子、哪些是学习近似。若使用Schur补、逆作用或低秩表示，交代如何应用，不能把未计算的精确逆当免费输入。

核算全物理域、缓存、临时数组、训练图及全部迭代。非线性/变预条件要匹配外层方法；检查零残差行为、相位/尺度约定、复杂介质界面、未见源与异常情况。无须每层都有物理解释，但承担贡献的运算必须清楚。

## 6. 判断与记录

研究阶段允许收益待验证，但不提前命名为已确立的创新。使用：

- **继续**：机制与问题明确，有值得验证的差异。
- **降级**：只作基线、局部思想或被更近先例覆盖。
- **停止**：偏离目标或已出现足以否决的障碍。
- **定向补证据**：指出哪项原文缺口会改变判断。

对外简报与方向README统一为**判断、依据、缺口、下一步**。详细来源只放papers或查重报告，设计和验证各存一次。科学实验结论依实际结果更新，不用文献论证冒充实验完成。
