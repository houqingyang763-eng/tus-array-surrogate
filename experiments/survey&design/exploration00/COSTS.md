# 三维成本：先约束计算，再决定骨架

本页是解析核算，不是V100实测。机器可读结果见[JSON](calculations/costs.json)，公式见[标准库脚本](scripts/cost_model.py)。所有张量按单样本、单GPU计；五卡global batch=5意味着每卡承担一份，不能将单样本显存除以五。

## 判断

- **判断：继续窄细层、多通道粗层、少量介质条件更新；停止直接放大全域attention、密集频域权重和深查询MLP。**
- **依据：**域内23,789,568体素。参数少和线性复杂度都不足以保证完整三维训练便宜；大激活、状态、工作区和反向成本必须分别计入。下表给出可复算数量级。
- **缺口：**实际V100型号/显存、卷积后端、跨卡通信和中间张量存活尚无本候选实测。解析数值用于删掉明显不合算的实现，4 s门限由完整更新计时决定。
- **下一步：**实现前先固定算子表；获运行授权后只作候选与对照的完整五卡更新测量，再进入精度比较。

## 单个张量，不是显存峰值

| 张量 | 大小 | 对设计的限制 |
|---|---:|---|
| 全ROI Re/Im，FP32 | 181.5 MiB | 输入、输出、梯度及临时归一化可同时存活 |
| 全ROI 8实通道，FP16 | 363 MiB | 细层宜窄；每多保留一份都要付费 |
| 全ROI 16实通道，FP16／FP32 | 726／1452 MiB | 细层多次迭代会累积反向保存量 |
| 1 mm 16实通道，FP16 | 90.75 MiB | 恰等于一份0.5 mm复场的重排数据量；尚未压缩 |
| 2 mm 48实通道，FP16 | 34.03 MiB | 可承载多个波分量，不等于可任意增加更新次数 |
| 8个全域复载波，FP32 | 1452 MiB | 按局部块生成，不显式常驻全域载波库 |
| 2 mm复状态：16通道×4状态，FP32，单方向 | 181.5 MiB | 六方向若分别保存为1089 MiB，还不含反向 |
| 全ROI复基底rank=32，FP32 | 5.672 GiB | 基底+梯度+Adam两动量约22.688 GiB；不作为密集可训练输出参数 |
| 510万mask体素复基底rank=32，FP32 | 1.216 GiB | 适合离线分块诊断；不是全ROI输出实现 |
| 全ROI×4096 token注意力分数，单头FP16 | 181.5 GiB | 全域密集注意力停止；稀疏/分解方案另算 |
| mask×4096 token注意力分数，单头FP16 | 38.924 GiB | 即使仅预测mask也不划算；尚有多头与反向 |
| 64×64通道、64³复谱权重，FP32，单存储块 | 8 GiB | 多频率符号块、梯度/优化器会再放大 |

FP16仅为存储核算，不授权改变当前训练精度。若复杂操作只能用FP32，须按真实实现重算。激活检查点可以用重算换显存，但重算计入4 s。

## 运算

实卷积MAC=`N·k³·Cin·Cout`；深度卷积加逐点混合MAC=`N·(k³·Cin+Cin·Cout)`。一MAC按两FLOP，以下仅前向，不把前向数字写成更新时间。

| 一层运算 | GMAC |
|---|---:|
| 0.5 mm密集3³卷积8→8 | 41.108 |
| 0.5 mm密集3³卷积16→16 | 164.433 |
| 0.5 mm密集3³卷积32→32 | 657.734 |
| 0.5 mm深度3³+逐点16→16 | 16.367 |
| 2 mm密集3³卷积64→64 | 41.108 |
| 全ROI、4次256→256查询隐藏变换 | 6236.293 |

粗层体素少64倍、通道增8倍后，密集卷积成本恰好回到细层8→8。因此“放粗层”也需要限制通道与迭代。深度卷积的实际吞吐可能受带宽限制，不能按MAC比值预测加速比。

## M0候选的可核算核心

对应[介质条件多尺度设计](medium_source/DESIGN.md)：细层8、1/2/4 mm层16/48/96个实通道，两次共享V-cycle；每个粗层两次初始局部块、每次cycle两次局部块，共六次。每个块另计逐点A运算。初始及两次cycle各计一次限制与延拓。细层两次局部块与输出头、源lift、介质门控和两轮rank8轴向全域混合均计入。

明确的lift选择：原介质C_m通道逐点映射到8实通道，经过一块细层局部编码后下采样为各尺度门控输入；1 mm的packed P0 16实通道+介质8+几何4，逐点28→16建立源状态。几何4为源距离及单位方向XYZ，由当前g与网格计算。细解码将逆重排场2+细介质8+几何4逐点14→8，再作一块细层局部块。全域初版不分块。

脚本得到明确卷积/矩阵核心前向**`81.963983 + 0.190317·C_m` GMAC**，C_m为实际输入介质通道数。[基线ROI hook记录](../../../docs/evidence/v10_baseline.md#results)确认介质1通道、P0两实通道，因此当前接口下为**82.154299 GMAC，约0.164309 TFLOP**。保留通道变量仅便于以后核算，不增加当前输入。遗漏项包括元素门控/激活/相加、几何特征生成、重排与插值、归一化、反向、重算、DDP及优化器。它支持“值得实施小候选”的判断，不支持“已达到4 s”。改变cycle个数、通道或模块时必须更新算子表。

同脚本按基线六级、每级两密集3³卷积、反卷积和decoder跳接后两卷积、输出头核算，普通主干为**360.103 GMAC前向**，尚不含条件融合/Fourier-FiLM。M0明确核心约为这一主干MAC的22.81%。这是不同算子的运算量比较，深度卷积/重排/多小kernel可能吞吐更差，不据此预测4.38倍加速。条件结构、norm与反向在实测中全部计入。

初版采用全域细层窄通路；若显存受阻，才考虑有halo的局部解码。分块不减少完整输出的总MAC，并可能增加重叠成本。全局粗状态覆盖整个ROI，分块仅改变局部运算调度。输入保持当前ROI合同，不把ROI外物理介质假装成已完整编码。

## 缓存口径

介质固定且模型权重固定时，介质特征和空间门控可在推理准备阶段缓存：分别报告冷启动、准备成本、单个新源与多源均摊成本。训练每次参数更新后门控发生变化，不能把上一轮缓存detach后复用而仍声称训练了介质编码器；当前4 s口径包含当步门控计算。五卡也不默认共享一份可求导缓存。
