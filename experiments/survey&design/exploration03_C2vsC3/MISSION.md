## 1. 目标与已纠正的定位

独立判断哪些传统求解基底值得投入网络加速，重点重审C2/C3。最终说明：现有方法实际做到了什么，为什么有这个性能，用于本项目预计怎样，网络能省掉什么，最终能否达到McMg那样的加速成果。

| 对象 | 本轮定位 |
| --- | --- |
| C2 | 优化两网格配粗层双向PML扫描；重新核验其三维成果、实际延迟与资源成本 |
| C3 | 递归多层deflation配CSLP；重新核验数小时结果、嵌套工作和并行表现；原“略优先”判断撤回 |
| McMg | **网络加速后的性能标杆与学习方法对照**；不归入传统算法，不默认迁移，不限定我们的办法 |
| 其他传统方法 | C2/C3的必要竞争者；有更强且贴近任务的成果时允许替换，不为保留旧推荐忽略反证 |

必须分别回答两个问题：传统实现今天是否具有工程竞争力；针对其瓶颈加速后是否有值得研究的潜力。慢方法不因有瓶颈就自动值得做，快方法也不因留给网络的空间小就被排除。

## 2. 项目任务保持一致

- 可更换介质；希望较快完成一次介质相关准备，随后处理多个临时源配置。不默认接受逐颅骨长时间训练。
- 同一配置为同频、线性传播的多个点源，最多几千个；可选位置不限定为几千个。先组成 `b = Σ_j a_j b(s_j)`，求一次 `A_m u = b`，输出**一份总复场形状**。
- K为同次源数，Q为同一介质下配置次数；二者不可混用。不默认建立逐源场库，不以多右端批处理吞吐代替单次配置延迟。
- 完整计算域384×480×224 @0.5 mm；临时网络/输出ROI为352×352×192。ROI不缩小传播介质。现有物理合同按[V10 handoff](../../../docs/project_design_handoff_v10.md)沿用。
- 输出为颅内Re/Im形状，内部保留相干叠加所需的相对幅度和相位，最后对总场联合归一化。禁用raw/绝对Pa验收。
- 很快且形状足够准，或稍慢且误差极小，均可竞争；当前没有指定唯一秒数/误差门槛，不替用户擅设硬阈值。

## 3. 成果证据必须提取什么

优先读论文展示成果的部分，结合相关方法细节、补充材料与作者实现解释；不能只读摘要或从方法名字推断性能。每行对应一个真实测试配置，至少包含：

| 证据项 | 要记录与判断的内容 |
| --- | --- |
| 实际求解对象 | 方程、未知量/分量、离散、边界；差异是否改变每步成本或收敛 |
| 三维与规模 | 真三维还是二维；物理域及工作域网格、未知量、边界层是否计入 |
| 波长尺度 | 频率、网格间距、每波长点数、跨域波长数；不只比较物理Hz或格点数 |
| 介质难度 | 参数范围/对比度、层状/盐丘/断层/薄壳等结构、跳变、散射与反射；不能用“复杂”二字代替 |
| 源与输出 | 单点、随机体右端、批量独立源或总源；输出范围；何种输入有缓存/流水线收益 |
| 结果与指标 | 原文场误差、残差定义/归一化、停止阈值、成功/失败、最好与代表结果、重复/均值范围 |
| 时间边界 | 墙钟或累计CPU时间、准备与求解、批吞吐与单次延迟、冷热缓存、真残差及输出；未列项不得默认为零 |
| 资源和版本 | CPU型号/核数/节点、GPU型号/数量、内存/显存、数值精度、实现及对应版本 |
| 训练和换介质 | 通用训练、逐介质适配、介质缓存、冻结权重的实际测试、源变化和介质变化分别记录 |
| 原文定位 | 正文页码/章节/图表、补充材料或代码固定版本；明确取值与本轮推算 |

已有卡片完整覆盖的字段复用，缺失/矛盾处定向回查原文。性能与复杂介质必须来自同一测试；二维高对比度、三维大尺寸和另一算例最快时间不能拼成一份成果。

## 4. 本轮必须完成的推理

### 4.1 为什么快、为什么慢

- C2：准备中分解占多少；在线局部三角解、扫描依赖、通信、平滑、外迭代分别承担什么；批多右端是否掩盖单配置延迟。
- C3：外步少而总时间长的原因；每层内迭代/粗解、传递模板、算子/正交化、构造与通信成本；用同文规模/参数/并行曲线区分算法、实现和资源因素。
- 对成小时的实现，核清时间定义与硬件；若快速在线目标下无现实竞争力，明确降级。若保留其改造价值，给出可消除成本和数量级依据。
- 对使用许多CPU的实现，同时看延迟、核时、内存、并行效率。核时仅表示资源用量，不能将不同CPU/GPU按核数直接折算性能。

原因要分为原文直接测量、由同文对照支持的推断、尚待核实的假设。不能把每一种可能瓶颈都写成既成事实。

### 4.2 迁移到本项目预计怎样

以可比三维实测为锚点，用规模/波长、每步工作、迭代增长、介质与算子变化、硬件能力形成有条件估计。分别给出：通用训练；换介质准备；首次与后续配置求解；峰值内存；精度/收敛预期。

给乐观、主要和保守区间，说明每项的假设和证据强弱；不能机械按格点数线性放大，也不能捏造精确秒数。硬件未冻结时按明确参考场景分别估计，不混成一个项目实测数字。不同配置用 `S_m + Q·T_online` 比较复用，准备成本与体输出不得消失。

原文残差和本项目形状误差保持各自含义。物理/任务差异只深入到会改变性能估计和选择的程度，不转成无边界模型审计；差异必须落到预期影响，不能成为拒绝判断的通用理由。

### 4.3 网络到底省多少

从已辨认的昂贵计算出发，给出利用的规律、网络输入/输出、替代/改善步骤和保留的真算子/停止检查；允许与McMg完全不同的办法，不先押某种骨干或粗层位置。

将总时间拆成可替代与保留部分，再加网络自身、缓存、通信和适配成本。用占比及加速上限检验：例如只消除90%的成本，总加速上限为10倍。从小时走到秒级，必须解释所需数量级的收益。无法找到足够大且可压缩的成本时，明确否决该学习位置。

比较对象包含该传统方案自身的强实现/调参、必要非学习替代与McMg成果。McMg的优势应承认；它的测试条件应如实核对。不能据它的结构规定我们必须复用哪种多网格、通道或缓存组织，也不能把其经典对照的时间写成McMg时间。

### 4.4 最后作选择

每条候选最终必须给出：现实速度与资源判断；本项目预测；最有价值的可改造瓶颈；预期收益及代价；相对竞争者的优势/劣势；推荐、条件保留或淘汰；把握与改判条件。

不止说“各有优缺点”。当前信息足以作出的判断当场作出；只能由项目实验确定的部分具体列明。允许C2、C3都不合适，不预设最优传统方案与最优学习课题是同一个。
